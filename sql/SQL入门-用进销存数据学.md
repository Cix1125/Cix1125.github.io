## 一、先说 SQL 是什么

**一句话：SQL 是"向表格提问"的语言。**

你现在的做法是：打开店铺后台，把数据导成 Excel，自己一行行看、拉公式算。
SQL 的做法是：**你把要求说清楚，它去算，直接给你答案。**

比如你想知道"哪些货快没了"：

- Excel 里：筛选 → 库存列 < 安全库存列 → 看结果
- SQL 里：`SELECT name FROM products WHERE stock < safety_stock;`

就这么一句话。**同一个意思，只是换了个说法。**

## 二、你项目里的三张表

这是你当初设计进销存时定下来的结构，SQL 就是围着这三张表转：

### `products` 商品表

| 字段 | 含义 |
|---|---|
| `id` | 商品编号（**身份证号**，下面两张表靠它找到这个商品） |
| `name` | 品名 |
| `sku` | 货号 |
| `price` | 单价 |
| `stock` | 账面库存（手填的，会出错） |
| `safety_stock` | 安全库存（低于它就该补货） |

### `stock_moves` 出入库流水表

| 字段 | 含义 |
|---|---|
| `id` | 流水号 |
| `move_date` | 日期 |
| `product_id` | 商品 id → 指向 `products.id` |
| `move_type` | `in` 入库 / `out` 出库 |
| `qty` | 数量 |
| `note` | 备注 |

### `orders` 订单表

| 字段 | 含义 |
|---|---|
| `id` | 订单号 |
| `customer` | 客户 |
| `product_id` | 商品 id → 指向 `products.id` |
| `qty` | 数量 |
| `status` | 待处理 / 已发货 / 已完成 / 已取消 |
| `order_date` | 下单日期 |

> **注意 `product_id` 这个字段。** 它是整个设计的枢纽——流水和订单里都不存商品名字，只存商品编号，需要名字的时候再去 `products` 表里查。**这就是"关系型"三个字的意思。**

## 三、核心思维：把中文问题翻译成 SQL

这是学 SQL 唯一真正的门槛。语法查得到，**翻译的思路**才要练。

| 你想问 | 翻译成 |
|---|---|
| 哪些货快没了？ | 从商品表里，**挑出**库存小于安全库存的 |
| 每个商品出库了多少？ | 从流水表里，**按商品分组**，把出库数量**加起来** |
| 8 月哪个卖得最好？ | 从订单表里，**只留 8 月的**，**按商品分组**求和，**从大到小排**，**取第一条** |
| 哪个客户的订单金额最大？ | 订单表要算金额，但单价在商品表里 → **把两张表连起来** |

四个动作，对应四个 SQL 关键词：

| 中文动作 | SQL 关键词 |
|---|---|
| **挑**（筛选行） | `WHERE` |
| **排**（排序）/ **取前几** | `ORDER BY` / `LIMIT` |
| **按…分组算** | `GROUP BY` + `SUM` / `COUNT` |
| **连表** | `JOIN` |

## 四、四个动作，一个个来

### 动作 1 · 挑：`SELECT` + `FROM` + `WHERE`

```sql
SELECT name, sku, price, stock
FROM products
WHERE stock < safety_stock;
```

读作：

- `SELECT name, sku, price, stock` —— **我要看这几列**
- `FROM products` —— **从商品表里**
- `WHERE stock < safety_stock` —— **只要满足这个条件的行**

> ⚠️ **最容易搞混的一点**：`SELECT` 写的是"我要哪几列"，`WHERE` 管的是"我要哪几行"。列和行，两回事。

**结果**：牛仔直筒裤（8 < 15）、帆布单肩包（3 < 12）——这两款该补货了。

---

### 动作 2 · 排和取：`ORDER BY` + `LIMIT`

```sql
SELECT name, stock
FROM products
ORDER BY stock ASC;      -- ASC 从小到大，DESC 从大到小
```

```sql
SELECT name, stock
FROM products
ORDER BY stock ASC
LIMIT 3;                 -- 只要前 3 条
```

> **"最……的是哪一个"** 这类问题，答案永远是 `ORDER BY ... DESC LIMIT 1`。记住这个套路。

---

### 动作 3 · 分组算：`GROUP BY` —— **就是数据透视表**

这是你简历上写的那一条，也是最有用的一个。

**没有 GROUP BY 的时候**，`SUM` 只能算全表总数：

```sql
SELECT SUM(qty) FROM stock_moves WHERE move_type = 'out';   -- 所有出库加起来 = 120
```

**加了 GROUP BY**，它就按你指定的那一列"分堆"，每堆各算各的：

```sql
SELECT p.name, SUM(m.qty) AS out_total
FROM stock_moves m
JOIN products p ON p.id = m.product_id
WHERE m.move_type = 'out'
GROUP BY p.name
ORDER BY out_total DESC;
```

**读法**：`GROUP BY p.name` = "按商品名字分堆"，`SUM(m.qty)` = "每堆把数量加起来"。

**结果**：

| 品名 | 出库总量 |
|---|---|
| 运动短裤 | 40 |
| 纯棉圆领T恤 | 28 |
| 牛仔直筒裤 | 22 |
| 针织开衫 | 15 |
| 帆布单肩包 | 15 |

> 💡 **如果你会用 Excel 的数据透视表，你就已经懂 GROUP BY 了。**
> 透视表里你拖一个字段到"行"，拖一个字段到"值"选求和——SQL 里就是 `GROUP BY 那个字段` + `SUM(这个字段)`。

**能在 `GROUP BY` 里用的计算**：

| 写法 | 意思 |
|---|---|
| `SUM(字段)` | 求和 |
| `COUNT(*)` | 数有几行 |
| `AVG(字段)` | 平均 |
| `MAX(字段)` / `MIN(字段)` | 最大 / 最小 |

### 动作 4 · 连表：`JOIN` —— **就是 VLOOKUP**

这是最需要理解的一个。先问：**为什么需要连表？**

因为数据拆开放了。你想知道"哪个客户买了什么"，但：

- `orders` 表里只有 `product_id`（商品编号），**没有商品名字**
- 商品名字在 `products` 表里

所以要**把两张表按商品编号拼起来**：

```sql
SELECT o.customer, p.name, o.qty
FROM orders o
JOIN products p ON p.id = o.product_id
```

**逐字读这句**：

| 片段 | 意思 |
|---|---|
| `FROM orders o` | 从订单表出发，给它起个小名叫 `o`（省得每次都写全名） |
| `JOIN products p` | 把商品表接进来，叫它 `p` |
| `ON p.id = o.product_id` | **连接条件**：商品表的 id 等于订单表的 product_id |

> 💡 **JOIN 就是 Excel 里的 VLOOKUP。**
> 订单表里有个商品编号，你拿这个编号去商品表里查出对应的名字，贴回来。SQL 只是把这个动作批量做了——**一次查完所有订单，不用往下拖公式。**

**结果**：

| customer | name | qty |
|---|---|---|
| 张小满 | 纯棉圆领T恤 | 3 |
| 李记服饰 | 牛仔直筒裤 | 10 |
| 散客 | 帆布单肩包 | 6 |
| … | … | … |

> **三种 JOIN，你现在只需要记一种**：
> - `JOIN`（内连接）：两边都有的才留下 —— **默认用它就够了**
> - `LEFT JOIN`（左连接）：左边全留，右边没有的填空 —— 算"每个商品"的库存时要用，因为有的商品可能一条流水都没有

## 五、一条完整查询的样子

```sql
SELECT   p.name,                          -- 要看什么
         SUM(o.qty) AS sold               -- 算出来的列，起个名
FROM     orders o                         -- 从哪张表
JOIN     products p                       -- 连哪张表
         ON p.id = o.product_id           -- 怎么连
WHERE    o.order_date >= '2026-08-01'     -- 筛行
         AND o.order_date <  '2026-09-01'
         AND o.status <> '已取消'
GROUP BY p.name                           -- 按什么分组
HAVING   SUM(o.qty) > 10                  -- 筛组（注意不是 WHERE）
ORDER BY sold DESC                        -- 排序
LIMIT    1;                               -- 取前几
```

**问题**：8 月份哪个商品卖得最好？ → **牛仔直筒裤，18 件。**

### ⚠️ 两个必须记住的点

**① 写法顺序 ≠ 执行顺序**

你写的时候是 `SELECT` 在最前面，但数据库**不是从 SELECT 开始算的**。它实际是：

```
FROM / JOIN  →  WHERE  →  GROUP BY  →  HAVING  →  SELECT  →  ORDER BY  →  LIMIT
先找到表      筛行      分组        筛组       挑列        排序         取前几
```

**所以：**
- `WHERE` 里**不能**用聚合函数（`SUM`/`COUNT`），因为那时还没分组
- 想筛"总数大于 10 的"，要用 `HAVING`

**② 看不懂一条 SQL 时，从 `FROM` 开始读，别从 `SELECT` 开始。**

先看"数据从哪来、怎么连的"，再看"要什么"，最后看"筛什么"。这个顺序和执行顺序一致，一看就通。

## 七、⭐ 对账那条为什么最值钱

Q6 的结果是：

| 品名 | 账面库存 | 流水算出来 |
|---|---|---|
| 帆布单肩包 | 3 | **5** |

**差 2 件。** 这件事的意义在哪：

- `products.stock` 是**手填的**——老板卖一件手动改一个数，漏改、错改都看不出来
- `stock_moves` 是**每笔留痕的**——只要认真记，累加起来就是真数
- **"账面和实际对不上"，正是小微商户最痛的三个问题之一**（另外两个是月末对账靠手工、缺货发现滞后）

这条查询就是**用数据把这个痛点抓出来**。它比"我会 JOIN"这句话有说服力一百倍。
